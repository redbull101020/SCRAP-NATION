# Testing — проверки и Definition of Done

[AGENTS](../../AGENTS.md) · [Simulation](Simulation.md) · [ECS](ECS.md) · [MVP playtests](../GameDesign/MVP.md)

Unity Test Framework. EditMode для правил/транзакций; PlayMode для Unity-адаптеров, сцен и lifecycle. Не строить тяжёлый тестовый фреймворк; добавлять проверки одновременно с соответствующей функцией. Seed и порядок операций явные; чистые правила не зависят от FPS/реального времени. Для ECS создавать изолированный тестовый World и освобождать его; не использовать global world как невидимую зависимость.

## Регрессия по этапам

| Этап | Проверки |
| --- | --- |
| P0/A | Два NPC на последней единице; вместимость; перенос и сдача сохраняют материальный баланс; отказ не меняет состояние; одинаковые входы дают воспроизводимый результат на той же конфигурации |
| A | Три элемента брони по одному до cap; upgrade один раз, тот же ID; прежнее снаряжение не остаётся второй копией; продвинутый NPC может работать; reservation освобождается при отмене/удалении цели |
| B | Тревога прерывает работу; мёртвый NPC не сдаёт груз; бросок списывает хлам; оспариваемый спот не завершает новый сбор; доставленная партия не исчезает; контроль разрешается явно |
| C | Угроза растёт с богатством/стоянкой и не обнуляется конвертацией склада в здание; переезд сбрасывает стоянку, сохраняет известность и допустимый груз; NPC узнаваем по ID/профессии; повтор команды не дублирует; ошибка загрузки не теряет последнюю сессию |
| Disk saves (позже) | Save/load round trip, версия схемы, ошибка/повреждённый файл, совместимость при заявленной миграции |

PlayMode: запустить сцену, проверить ввод/камеру/смену визуального состояния; UI читает simulation и не начисляет ресурсы. Остановить и запустить повторно, в том числе при отключённом Domain Reload: без старых таймеров, подписок, NativeContainers, NPC, чужого прогресса. При C повторно загрузить сцену и проверить отсутствие двойного clock/session.

## Тесты из CLI

Примеры, когда редактор установлен, проект импортирован и Test Framework доступен (пути подставить локально, создать OutputDir):

```sh
"<UnityEditor>" -batchmode -nographics -projectPath "<UnityProjectRoot>" -runTests -testPlatform EditMode -testResults "<OutputDir>/editmode.xml" -logFile "<OutputDir>/editmode.log"
"<UnityEditor>" -batchmode -projectPath "<UnityProjectRoot>" -runTests -testPlatform PlayMode -testResults "<OutputDir>/playmode.xml" -logFile "<OutputDir>/playmode.log"
```

Учитывать точную версию Test Framework, графическое окружение и Unity license. Не добавлять -quit, если это может прервать выполнение тестов. Проверять код возврата, XML и лог: запуск без выполненных тестов не является успехом. CI добавлять, когда есть проект и поддерживаемый runner, не ради документа.

Профилирование — по [ECS.md](ECS.md). Игровой плейтест — по [MVP.md](../GameDesign/MVP.md). Успешные unit tests не доказывают интерес игры и не заменяют PlayMode.

## Definition of Done

- Затронутый сценарий реализован в нужном объёме; нет незапрошенных изменений.
- Проверены компиляция, ссылки на ассеты, целевой PlayMode и правила тестами, когда среда доступна.
- Нет новых неожиданных Console errors в проверенном сценарии; ограничения названы.
- При недоступном редакторе/лицензии указать, что не запускалось, и воспроизводимую процедуру проверки. Не выдавать diff/static review за компиляцию.
- Обновить документацию, если изменился контракт; в отчёте файлы, результаты, допущения и риски. Не маскировать ошибки удалением тестов или валидаторов.
