# NPC — автономность, работа и эволюция

[Концепция](Concept.md) · [Экономика](Economy.md) · [Симуляция](../Architecture/Simulation.md)

## Поведение

Куча мусора и здания создают рабочие возможности. NPC приходят в поисках работы при наличии подходящих мест; MVP использует ограниченный приток жителей, а не бесконечный spawn при каждой куче. Старт два бродяги; рост до 4–8 в A–C по балансу. Герой меняет приоритеты/доступность работ, а не выбирает цель каждого NPC. Игроку читаемо показывать текущую цель, причину и личный прогресс.

NPC выбирает задачу, резервирует слот, подходит, выполняет действие, завершает или отменяет его. При недоступности цели освобождает reservation и выбирает новую; idle не должен постоянно пересчитывать все цели. Тревога и опасность могут прервать работу; при возврате прежняя задача заново проверяется. Профессия и личность не исчезают.

## Первые две ветки

| Начальный NPC | Мирная работа и бой | Улучшение | Результат |
| --- | --- | --- | --- |
| Сборщик с тележкой | Собирает хлам, в ломбарде сдаёт груз; в B может метать содержимое тележки, расходуя его | Личный прогресс от фактически сданного груза + доступный ломбард + ресурсы | Гарпунщик |
| Барахольщик | По одному надевает найденные элементы брони; в B временная защита изнашивается | Комплект до cap + металлоприёмник + оплата улучшения | Железник |

В A сражения не нужны: улучшение должно быть видно без них. Каждый предмет брони извлекается из конечной залежи. При переплавке временная броня исчезает из экипировки, поступает как хлам и часть ресурса оплачивает стандартизированное снаряжение. Потерянный/израсходованный предмет нельзя сдать. Не делать временный комплект, HP и прогресс одной переменной.

**Не допустить исчезновения рабочих:** в MVP гарпунщик сохраняет возможность собирать/доставлять хлам (тележка или упрощённый груз), железник помогает с добычей/переноской или ремонтом. В бою оба специализируются на защите. Точное визуальное решение для мирной работы открыто. Позже разрешать альтернативные профессии и специализацию через здания; не требовать отдельного рабочего класса для проверки A.

## Модель поведения

Разделять независимые аспекты, но выполнять только одно конфликтующее действие за раз.

| Аспект | Пример |
| --- | --- |
| Profession | Scavenger, ScrapGuard, Harpooner, IronGuard |
| Task | Collect, Deliver, Equip, Upgrade, Defend, Retreat, Repair |
| Activity | Idle, Moving, Working, Attacking |
| CombatMode | Peaceful, Alert, Engaged |
| PersonalProgress | Накопленный прогресс от сдачи / условия перехода |
| Equipment / Cargo | Отдельные текущие предметы или количества, броня и груз |

Пример: сборщик с Task=Deliver и Activity=Moving при тревоге приостанавливает доставку. Если приоритет обороны требует вступить в бой, переход в Defend освобождает reservation здания; после боя оставшийся груз доставляется только после проверки цели. Не считать Activity и Task независимыми FSM без общего арбитра.

Приоритеты в B: смерть/недоступность действия → отступление или мобилизация по правилам зоны → текущая допустимая задача → новая работа. Task может завершиться только единожды. Конкретные расстояния, таймеры и правила выбора — конфиг. Utility AI добавлять, только если простая FSM с приоритетами недостаточна.

## Постоянная личность и внешний вид

NPC имеет стабильный ID, имя (минимум для узнаваемости), профессию, экипировку, здоровье, личный прогресс. Смена профессии меняет правила и view по тому же ID, не спавнит нового жителя. При переезде ID, профессия и экипировка сохраняются.

В A обязательна читаемая смена внешнего вида: тележка, последовательные элементы брони, гарпун, единый комплект железника. Никакой полноценной системы инвентаря предметов с уникальными GUID не требуется: счётчиков и 3 фиксированных слотов достаточно, пока механика не требует большего.
